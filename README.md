# CRediT Contributor Roles Parser & Normalizer

An automated tool that dynamically fetches the official 14 CRediT (Contributor Roles Taxonomy) definitions directly from [credit.niso.org](https://credit.niso.org/) at runtime, extracts author contributor roles from academic manuscript Word documents (`.docx`), normalizes them to the live-fetched standard roles, and outputs a structured CSV.

---

## Key Features

1. **Strictly Zero Hardcoding**:
   - The 14 official CRediT roles are scraped dynamically from `https://credit.niso.org/` at runtime.
   - Individual role definitions and task examples are harvested concurrently to power dynamic TF-IDF semantic role matching.
2. **Author Name Cleansing & Resolution**:
   - Dotted initials (`J.D.` &rarr; Jane Doe, `A.B.` &rarr; Anil Bose) and compact undotted initials (`AB`, `CD`, `EF`).
   - Cleans academic titles (`Dr.`, `Prof.`) and affiliation/footnote symbols (`1*`, `2†`).
   - Disambiguates compound author statements (`AB and CD wrote and edited the paper`).
   - Expands collective authorship (`All authors contributed equally to...`).
3. **Semantic Role Normalization**:
   - Direct matching, casing normalisation (`FORMAL ANALYSIS` &rarr; `Formal analysis`), and punctuation handling.
   - Strips degree qualifiers (`Conceptualization – lead` &rarr; `Conceptualization`).
   - Free-form narrative semantic mapping:
     - *"wrote initial draft"* / *"wrote the manuscript"* &rarr; **Writing – original draft**
     - *"designed the study"* &rarr; **Conceptualization**
     - *"performed the experiments"* / *"collected the data"* &rarr; **Investigation**
     - *"analyzed the data"* / *"performed statistical analysis"* &rarr; **Formal analysis**
     - *"created the figures"* &rarr; **Visualization**
     - *"edited the final text"* / *"reviewed and edited"* &rarr; **Writing – review & editing**
     - *"acquired funding"* &rarr; **Funding acquisition**
     - *"administered the project"* &rarr; **Project administration**
     - *"provided resources"* &rarr; **Resources**
     - *"supervised the project / work"* &rarr; **Supervision**
     - *"Developed code (Software)"* &rarr; **Software**
   - Non-academic / joke tasks (*"made the tea"*) are rejected and marked as `INVALID`.
4. **Resilience & Edge-Case Handling**:
   - Gracefully handles corrupted files (e.g. `merged_12.docx`) without crashing batch execution.
   - Distinguishes between actual contribution sections and bibliography citations in References (e.g. `merged_13.docx`).
   - Marks manuscripts without contributorship statements as `INVALID` (e.g. `merged_09.docx`, `merged_11.docx`).
5. **Zero External Dependencies**:
   - Implemented using 100% Python standard library (`urllib`, `xml.etree`, `zipfile`, `concurrent.futures`, `csv`, `difflib`).
   - Runs out-of-the-box on clean Ubuntu machines with Python 3.12+.

## How to Run

### 1. Running the Tool via `run.sh`

```bash
./run.sh <input_folder> <output.csv>
```

**Example:**
```bash
./run.sh manuscripts/ output.csv
```

### 2. Running Automated Tests

To execute the test suite and automatically generate `test_report.csv`:

```bash
python3 test_credit_parser.py
```

The test runner will execute all unit and integration tests, verify assertions, and write the summary to `test_report.csv` at the root directory.

---

## Output CSV Schema

The generated CSV contains a header row followed by one row per author-role pair:

```csv
file,author,credit_role
merged_01.docx,Jane Doe,Conceptualization
merged_01.docx,Jane Doe,Writing – original draft
merged_01.docx,Anil Bose,Methodology
merged_01.docx,Anil Bose,Software
...
merged_09.docx,Sara Khan,INVALID
merged_09.docx,Leo Moreau,INVALID
merged_12.docx,,INVALID
```

- `file`: The manuscript filename.
- `author`: The resolved, cleaned author name.
- `credit_role`: The normalized canonical CRediT role dynamically fetched from `credit.niso.org`, or `INVALID` if valid contributorship cannot be determined or if live fetch fails.

## Test Report Specification (`test_report.csv`)

The automated test suite writes `test_report.csv` with the following columns:

| Column | Description |
|---|---|
| `checks` | Human-readable description of what the test verifies |
| `input` | The input text, URL, or document under test |
| `expected` | The expected output value |
| `actual` | The actual output returned by the system |
| `result` | `PASS` or `FAIL` |

## Requirements & Compatibility

- **OS**: Clean Ubuntu Linux (20.04/22.04/24.04), macOS, or Windows
- **Runtime**: Python 3.12+ (also compatible with Python 3.10+)
- **Network**: Internet access to fetch live definitions from `https://credit.niso.org/`
- **Dependencies**: None (Python standard library only)
